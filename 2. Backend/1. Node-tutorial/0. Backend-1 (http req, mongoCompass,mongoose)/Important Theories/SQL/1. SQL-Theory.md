# TYPES OF KEYS:

1. Primary Key - A Primary Key is a column (or set of columns) that uniquely identifies every row in a table. It must contain unique values, cannot contain NULL values, and each table can have only one Primary Key.

Example:
employee_id
101
102
103

Every employee has a unique employee_id.


2. Foreign Key - A Foreign Key is a column that refers to the Primary Key of another table to create a relationship between the two tables. It maintains referential integrity, allows duplicate values, and can contain NULL values unless restricted.

Example: 

Employees Table:

employee_id	        department_id
101	                    10
102	                    20

Departments Table:

department_id	    department_name
10	                    IT
20	                    HR

FOREIGN KEY(department_id)
REFERENCES Departments(department_id)

Meaning:
Employee → Department → IT



3. Candidate Key - A Candidate Key is any column (or combination of columns) that uniquely identifies every row in a table. It must contain unique values, cannot contain NULL values, and a table can have multiple Candidate Keys.

Example:
employee_id
email
aadhaar_no

All three uniquely identify an employee. Hence, all three are Candidate Keys.



4. Alternate Key - An Alternate Key is a Candidate Key that was not selected as the Primary Key. It still contains unique and non-NULL values, and a table can have multiple Alternate Keys.

Example:

If
PRIMARY KEY(employee_id)

Then
email
aadhaar_no

become Alternate Keys.



5. Super Key : A Super Key is any column or combination of columns that uniquely identifies a row in a table. It may contain extra unnecessary columns, and a table can have multiple Super Keys. The smallest Super Key is called a Candidate Key.

Example: 
employee_id
email
aadhaar_no
employee_id + email
employee_id + phone
employee_id + first_name


All of these uniquely identify a record.

Smallest Super Key

↓

Candidate Key

6. Composite Key - A Composite Key is a Primary Key formed using two or more columns. Individual columns may contain duplicate values, but their combination must uniquely identify every row.

Example:
employee_id	    project_id
101	                P1
101	                P2
102	                P1


Neither column alone is unique.

Together: employee_id + project_id

becomes unique.

PRIMARY KEY(employee_id, project_id)


7. Natural Key - A Natural Key is a real-world attribute that is naturally unique and already exists in the data. It has business meaning and can be used as a Candidate Key or even a Primary Key.

Example:
email
aadhaar_no
passport_number

These values are naturally unique in real life.


8. Surrogate Key - A Surrogate Key is a system-generated artificial key with no business meaning. It is automatically generated by the database, always unique, and commonly used as the Primary Key.

Example:
employee_id SERIAL PRIMARY KEY

Database generates - 
employee_id
101
102
103

automatically.





# SQL IMPORTANT CLAUSES:
A clause is a part of an SQL query that performs a specific operation.

1. SELECT Clause - Used to fetch data.

Example:

SELECT name 
FROM users;

Output:

Ayush
Rahul


2. FROM Clause - Specifies table.

SELECT *
FROM users;


3. WHERE Clause - Filters rows.

Example: users Table

id	   name	  age
1	     Ayush	21
2	     Rahul	17

Query:

SELECT *
FROM users
WHERE age >= 18;

Output - Ayush


4. ORDER BY Clause - Sorting.

Ascending:

SELECT *
FROM users
ORDER BY age ASC;

Descending:

SELECT *
FROM users
ORDER BY age DESC;


5. GROUP BY Clause - Groups similar values.

Example: 
Orders:
  city	    orders
  Delhi	      10
  Delhi	      20
  Mumbai	     5

Query:

SELECT city, COUNT(*)
FROM orders
GROUP BY city;

Output:

* Delhi 2
* Mumbai 1


6. HAVING Clause - Condition on groups.

SELECT city, COUNT(*)
FROM orders
GROUP BY city
HAVING COUNT(*) > 5;

Difference:

* WHERE → filters rows
* HAVING → filters groups


7. LIMIT Clause - Restrict output.

SELECT *
FROM users
LIMIT 5;

Output - Only first 5 rows.


8. AS - Rename columns or tables temporarily.

SELECT
    name AS Product_Name,
    price AS Product_Price
FROM products;






# IMPORTANT SQL CONSTRAINTS: 

Constraints are rules applied to columns in a table to ensure that only valid, accurate, and consistent data is stored in the database. They help maintain data integrity, prevent invalid entries, avoid duplicate data, and establish relationships between tables. Without constraints, a database could contain incorrect or inconsistent information, making applications unreliable.

| **Constraint**  | **Definition**                                                                             | **Example**                          |
| --------------- | ------------------------------------------------------------------------------------------ | ------------------------------------ |
| 1. PRIMARY KEY  | Uniquely identifies each row in a table. Cannot contain NULL or duplicate values.          | `id SERIAL PRIMARY KEY`              |
| 2. NOT NULL     | Ensures that a column must always have a value and cannot be left empty.                   | `name VARCHAR(100) NOT NULL`         |
| 3. UNIQUE       | Ensures all values in a column are unique; duplicate values are not allowed.               | `email VARCHAR(255) UNIQUE`          |
| 4. DEFAULT      | Assigns a default value to a column if no value is provided during insertion.              | `created_at TIMESTAMP DEFAULT NOW()` |
| 5. CHECK        | Validates data by allowing only values that satisfy a specified condition.                 | `age INT CHECK (age >= 18)`          |
| 6. FOREIGN KEY  | Creates a relationship between two tables by referencing the primary key of another table. | `user_id INT REFERENCES users(id)`   |






# SQL AGGREGATE FUNCTIONS:

Aggregate functions are SQL functions that perform calculations on multiple rows and return a single result. They are commonly used to calculate totals, averages, minimums, maximums, and counts of records.

1. COUNT() - Counts the total number of rows (or non-NULL values) in a table.

SELECT COUNT(*) AS Total_Products
FROM products;


2. SUM() - Adds all the numeric values of a column.

SELECT SUM(stock_quantity) AS Total_Stock
FROM products;


3. AVG() - Calculates the average value of a numeric column.

SELECT AVG(price) AS Average_Price
FROM products;


4. MIN() - Returns the smallest value in a column.

SELECT MIN(price) AS Cheapest_Product
FROM products;


5. MAX() - Returns the largest value in a column.

SELECT MAX(price) AS Most_Expensive_Product
FROM products;






# SQL SET FUNCTIONS:

Set Operators are used to combine the results of two or more SELECT statements. The SELECT queries must have the same number of columns, same order, and compatible data types.

1. UNION - Combines the results of two SELECT statements and removes duplicate rows.(it's unique)

SELECT name
FROM customers
UNION
SELECT name
FROM suppliers;

Output:-
Ayush
Rahul
Simran
Rohan

(Duplicates removed)


2. UNION ALL - Combines the results of two SELECT statements including duplicate rows.

SELECT name
FROM customers
UNION ALL
SELECT name
FROM suppliers;

Output:-
Ayush
Rahul
Rahul
Simran
Rohan

(Duplicates are kept)


3. INTERSECT - Returns only the rows that are common in both SELECT statements.

SELECT name
FROM customers
INTERSECT
SELECT name
FROM suppliers;

Output:-
Rahul

(Only common records)


4. EXCEPT - Returns rows from the first SELECT statement that are not present in the second SELECT statement.

SELECT name
FROM customers
EXCEPT
SELECT name
FROM suppliers;

Output:-
Ayush





# SQL STRING FUNCTIONS:

String functions are SQL functions used to manipulate, format, search, and extract text data stored in string (VARCHAR, CHAR, TEXT) columns.

1. UPPER() - Converts all characters in a string to uppercase.

SELECT UPPER(name) AS Product_Name
FROM products;


2. LOWER() - Converts all characters in a string to lowercase.

SELECT LOWER(name) AS Product_Name
FROM products;


3. LENGTH() - Returns the number of characters in a string.

SELECT LENGTH(name) AS Name_Length
FROM products;


4. CONCAT() - Joins two or more strings into a single string.

SELECT CONCAT(name, ' - ', category) AS Product_Details
FROM products;


5. TRIM() - Removes leading and trailing spaces from a string.

SELECT TRIM('   Coffee Beans   ') AS Clean_Text;


6. LTRIM() - Removes spaces from the left side of a string.

SELECT LTRIM('   Coffee Beans') AS Left_Trimmed;


7. RTRIM() - Removes spaces from the right side of a string.

SELECT RTRIM('Coffee Beans   ') AS Right_Trimmed;


8. SUBSTRING() - Extracts a portion of a string.

SELECT SUBSTRING(name, 1, 5) AS First_Five_Chars
FROM products;


9. LEFT() - Returns the specified number of characters from the left side.

SELECT LEFT(name, 4) AS Left_Text
FROM products;


10. RIGHT() - Returns the specified number of characters from the right side.

SELECT RIGHT(name, 3) AS Right_Text
FROM products;


11. POSITION() - Returns the position of a substring within a string.

SELECT POSITION('Tea' IN name) AS Position
FROM products;


12. REPLACE() - Replaces all occurrences of a substring with another substring.

SELECT REPLACE(name, 'Coffee', 'Tea') AS Updated_Name
FROM products;


13. REPEAT() - Repeats a string a specified number of times.

SELECT REPEAT('SQL ', 3) AS Output;


14. REVERSE() - Reverses the characters in a string.

SELECT REVERSE(name) AS Reversed_Name
FROM products;


15. INITCAP() - Converts the first letter of each word to uppercase.

SELECT INITCAP(name) AS Proper_Name
FROM products;


16. LPAD() - Pads the left side of a string with specified characters.

SELECT LPAD(name, 15, '*') AS Padded_Name
FROM products;


17. RPAD() - Pads the right side of a string with specified characters.

SELECT RPAD(name, 15, '*') AS Padded_Name
FROM products;


18. ASCII() - Returns the ASCII value of the first character.

SELECT ASCII('A') AS ASCII_Value;


19. CHR() - Returns the character represented by an ASCII code.

SELECT CHR(65) AS Character;


20. SPLIT_PART() - Splits a string using a delimiter and returns the specified part.

SELECT SPLIT_PART('Coffee-Beans-Premium', '-', 2) AS Part;






# SQL NULL HANDLING:

NULL handling functions are used to work with NULL (missing or unknown) values in SQL. They help replace NULLs, compare values, and filter records containing NULL values.

1. IS NULL - Checks whether a column contains a NULL value.

SELECT *
FROM products
WHERE category IS NULL;


2. IS NOT NULL - Checks whether a column contains a non-NULL value.

SELECT *
FROM products
WHERE category IS NOT NULL;


3. NULLIF() - Returns NULL if two expressions are equal; otherwise returns the first expression.

SELECT NULLIF(stock_quantity, 0) AS Stock
FROM products;




# SQL ALTER AND CASE:

The ALTER statement is used to modify the structure (schema) of an existing database object such as a table without affecting the existing data.

Using ALTER, you can:

* Add new columns
* Remove existing columns
* Rename columns
* Rename tables
* Change data types
* Add constraints
* Remove constraints


1. ADD COLUMN - Add a new column.

ALTER TABLE products
ADD COLUMN brand VARCHAR(50);


2. DROP COLUMN - Remove a column.

ALTER TABLE products
DROP COLUMN brand;


3. RENAME COLUMN - Rename an existing column.

ALTER TABLE products
RENAME COLUMN name TO product_name;


4. CHANGE DATA TYPE - Suppose price is INT and now you want decimals.

ALTER TABLE products
ALTER COLUMN price TYPE NUMERIC(10,2);



5. SET DEFAULT VALUE - Suppose new products should be available by default.

ALTER TABLE products
ALTER COLUMN is_available
SET DEFAULT TRUE;



6. REMOVE DEFAULT VALUE:-

ALTER TABLE products
ALTER COLUMN is_available
DROP DEFAULT;



7. SET NOT NULL - Make category compulsory.

ALTER TABLE products
ALTER COLUMN category
SET NOT NULL;


8. DROP NOT NULL - Allow NULL values.

ALTER TABLE products
ALTER COLUMN category
DROP NOT NULL;


9. RENAME TABLE:- 

ALTER TABLE products
RENAME TO flipkart_products;


10. ADD CONSTRAINT - Suppose we forgot UNIQUE on sku_code.

ALTER TABLE products
ADD CONSTRAINT unique_sku UNIQUE(sku_code);


11. DROP CONSTRAINT:-

ALTER TABLE products
DROP CONSTRAINT unique_sku;



# CASE Statement in SQL:
The CASE statement works like an IF-ELSE statement in programming languages. It checks one or more conditions and returns a value based on the first condition that evaluates to TRUE.

It is commonly used to:
* Create custom labels
* Categorize data
* Replace values
* Perform conditional calculations
* Improve report readability


Syntax:

SELECT
column_name,
CASE
    WHEN condition1 THEN result1
    WHEN condition2 THEN result2
    ELSE result
END AS alias_name
FROM table_name;


Example 1 (Price Tag):-
Suppose we want:

* Price > 1000 → Expensive
* Price between 500 and 1000 → Moderate
* Otherwise → Cheap

SELECT
    name,
    price,
    CASE
        WHEN price > 1000 THEN 'Expensive'
        WHEN price BETWEEN 500 AND 1000 THEN 'Moderate'
        ELSE 'Cheap'
    END AS price_tag
FROM products;


Example 2 (Availability Status): Convert Boolean values into readable text.

SELECT
    name,
    CASE
        WHEN is_available THEN 'In Stock'
        ELSE 'Out of Stock'
    END AS availability_status
FROM products;


Example 3 (Stock Level):-

SELECT
    name,
    stock_quantity,
    CASE
        WHEN stock_quantity > 100 THEN 'High Stock'
        WHEN stock_quantity BETWEEN 30 AND 100 THEN 'Medium Stock'
        ELSE 'Low Stock'
    END AS stock_level
FROM products;


Example 4 (Discount Category):-

SELECT
    name,
    price,
    CASE
        WHEN price >= 1500 THEN '20% Discount'
        WHEN price >= 1000 THEN '10% Discount'
        ELSE 'No Discount'
    END AS discount
FROM products;


Example 5 (Stock Alert):-
SELECT
    name,
    stock_quantity,
    CASE
        WHEN stock_quantity <= 20 THEN 'Order Immediately'
        WHEN stock_quantity <= 50 THEN 'Running Low'
        ELSE 'Sufficient Stock'
    END AS stock_alert
FROM products;


Example 6 (Category Type):-
SELECT
    name,
    category,
    CASE
        WHEN category = 'Electronics' THEN 'Electronic Item'
        WHEN category = 'Fitness' THEN 'Fitness Item'
        ELSE 'Other'
    END AS category_type
FROM products;


Example 7 (Rating Based on Price):-
SELECT
    name,
    price,
    CASE
        WHEN price > 1500 THEN 'Premium'
        WHEN price > 800 THEN 'Standard'
        ELSE 'Budget'
    END AS product_type
FROM products;


CASE with Aggregate Functions: Count available and unavailable products in a single query.

SELECT
    SUM(
        CASE
            WHEN is_available THEN 1
            ELSE 0
        END
    ) AS available_products,

    SUM(
        CASE
            WHEN NOT is_available THEN 1
            ELSE 0
        END
    ) AS unavailable_products
FROM products;


CASE with ORDER BY: Show available products first.

SELECT
    name,
    is_available
FROM products
ORDER BY
CASE
    WHEN is_available THEN 1
    ELSE 2
END;





# TYPES OF RELATIONSHIPS AND SQL JOINS: 

A relationship defines how two tables are connected using Primary Key (PK) and Foreign Key (FK).

1. One-to-One (1:1) :-

One record in Table A is related to only one record in Table B.

Example: One Student → One Student Profile

Students                        Student_Profiles
---------                      -------------------
student_id (PK)                 student_id (FK)
name                            address
                                phone
                                age

SELECT s.name, sp.address
FROM students s
JOIN student_profiles sp
ON s.student_id = sp.student_id;


2. One-to-Many (1:M) :-

One record in first table can have multiple records in second table.

Example: One Student → Many Marks

Students                      Marks
---------                   --------- 
1   Ayush                   1   English
                            1   Maths
                            1   Science

SELECT s.name,
       m.subject,
       m.marks
FROM students s
JOIN marks m
ON s.student_id=m.student_id;


3. Many-to-Many (M:M)

Many records from first table relate to many records from second table.

Needs a Junction (Bridge) Table:

Students                  Courses
---------               ------------
1   Ayush               101     SQL
2   Simran              102     Python



Student_Courses

1 101
1 102
2 102


SELECT s.name,
       c.course_name
FROM students s
JOIN student_courses sc
ON s.student_id=sc.student_id
JOIN courses c
ON sc.course_id=c.course_id;





# SQL JOINS:-

Joins combine rows from multiple tables using a related column.

Usually:
PK  ←→  FK


* INNER JOIN - Returns only matching rows.

SELECT *
FROM students s
INNER JOIN marks m
ON s.student_id=m.student_id;



* LEFT JOIN - Returns all rows from left table and matching row from right table and null if no match.

SELECT *
FROM products p
LEFT JOIN orders o
ON p.product_id=o.product_id;


* RIGHT JOIN - Returns all rows from right table and matching row from left table and null if no match.

SELECT *
FROM products p
RIGHT JOIN orders o
ON p.product_id=o.product_id;


* FULL JOIN - Returns all rows whether matching or matching rows from both tables.

SELECT *
FROM products p
FULL JOIN orders o
ON p.product_id=o.product_id;


* CROSS JOIN(Cartesian Product) - Returns every row with every row.

Cartesian Product:
3 × 4 = 12 rows

SELECT *
FROM colors
CROSS JOIN sizes;


* SELF JOIN - Join a table with itself.

Example: Employee → Manager

SELECT
e.name Employee,
m.name Manager
FROM employees e
JOIN employees m
ON e.manager_id=m.employee_id;



# SQL VIEWS AND PROCEDURES:

A View is a virtual table created using a SQL query. It stores the query, not the data.

Q. Why Views?
* Simplify Long Queries - Views save complex SQL queries under a single name, so you don't have to write the same joins and conditions repeatedly. This makes queries shorter, easier to read, and less error-prone.

* Security - Views allow users to access only specific rows or columns without exposing the entire table. This helps protect sensitive data such as salaries, passwords, or personal information.

* Reuse Logic - A view stores frequently used query logic that can be reused across multiple reports and applications. If the logic changes, you only need to update the view instead of modifying every query.

* Hide Complexity - Views hide complex joins, calculations, and filtering behind a simple table-like interface. Users can query the view as if it were a normal table without knowing the underlying SQL.


Example:

CREATE:-

CREATE VIEW expensive_products AS
SELECT
name,
price
FROM products
WHERE price>1000;


USE:-

SELECT *
FROM expensive_products;


DELETION:-
DROP VIEW expensive_products;



# PROCEDURES :-

A Procedure is a stored SQL program that performs one or more tasks.

Think of it as a SQL function that can execute multiple SQL statements.

Benefits:

* Reusable - A stored procedure can be written once and executed multiple times whenever needed. This reduces code duplication and makes database maintenance easier.

* Faster - Stored procedures are compiled and stored in the database, so they execute more efficiently than sending multiple SQL statements repeatedly. They also reduce network traffic between the application and the database.

* Secure - Users can be given permission to execute a procedure without direct access to the underlying tables. This helps protect sensitive data and prevents unauthorized operations.

* Encapsulation - Complex SQL queries and operations are hidden inside the procedure, providing a simple interface for users. This keeps the database code organized and easier to maintain.

* Business Logic - Business rules such as salary calculations, order processing, or inventory updates can be stored inside procedures. This ensures the same logic is consistently applied across all applications using the database.

SYNTAX:
CREATE PROCEDURE procedure_name()

LANGUAGE plpgsql

AS $$

BEGIN

END;

$$;


Example:
CREATE PROCEDURE add_product(
p_name VARCHAR,
p_price NUMERIC
)

LANGUAGE plpgsql
AS $$

BEGIN
INSERT INTO products(name,price)
VALUES(p_name,p_price);

END;

$$;


EXECUTION:
CALL add_product(
'Laptop',
65000
);



# COMMON TABLE EXPRESSIONS (CTE):-

A CTE is a temporary named result set that exists only for a single query. It makes complex queries easy to read.

SYNTAX:
WITH cte_name AS
(
    SELECT ...
)
SELECT *
FROM cte_name;


Example:
WITH expensive_products AS
(
SELECT *
FROM products
WHERE price>1000
)
SELECT *
FROM expensive_products;


MULTIPLE CTEs:
WITH

cte1 AS
(
...
),

cte2 AS
(
...
)

SELECT *
FROM cte2;
