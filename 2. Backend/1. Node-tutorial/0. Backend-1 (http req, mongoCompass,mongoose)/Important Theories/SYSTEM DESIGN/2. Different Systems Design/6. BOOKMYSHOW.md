# USAGE OF MESSAGE QUEUES:
ONCE USER WILL BOOK A SEAT, WE WILL SEND HIM NOTIFICATION VIA EMAIL OR SMS. USER WILL MAKE A THIRD PARTY API CALL HERE(A NETWORK CALL ADDING LATENCY TO THE SYSTEM). IN THE SAME API CALL FOR TICKET BOOKING WE CANT HANDLE ALL OF THESE TASK SYNCHRONOUSLY. SO AS SOON AS APP SERVER WILL SEND THE CONFIRMATION THAT USER HAS SUCCESSFULLY PAID FOR THE TICKET, THEN IT WILL SIMPLY SEND THIS DATA TO MESSAGING QUEUE AND  WHICH INSTRUCTS TO SEND NOTIFICATION VIA EMAIL/OTP ASYNCHRONOUSLY.



# HOW TO MANAGE CONCURRENT BOOKING IN OUR SYSTEM?
WHEN CLIENT OPENS THE APP, THE APP SERVER BASED ON HIS LOCATION SHOWS HIM THE THEATRES AVAILABLE BASED ON DATA RETRIEVED FROM REDIS CACHE IF AVAILABLE OR IF NOT THEN SQL DATABASE. AFTER APP SERVER WILL GET THE INFORMATION OF THEATRE THEN IT WILL QUERY THE THEATRE'S DATABASE. A ROW WILL BE LOCKED SO THAT OTHER USER WONT BE ABLE TO READ/WRITE FROM THAT PARTICULAR ROW AND USER COULD GET A SEAT FROM IT. ONCE PAYMENT IS DONE BY USER, THE PAYMENT SERVICE WILL SEND CALLBACK EVENT TO APP SERVER. THEN APP SERVER WILL UNLOCK THE ROW. THEN APP SERVER WILL SEND THE DATA TO MESSAGING QUEUE, NOW YOU CAN TAKE IT TO USER VIA SMS/EMAIL.  


# CASE WHERE THERE IS ONLY ONE APP SERVER, THEN HOW WILL WE MANAGE CONCURRENT BOOKING:
WHEN THERE IS ONLY ONE APP SERVER, THEN WE WILL WE MANAGE CONCURRENT BOOKING AT THE APPLICATION LEVEL. IN NODE, ...


# CASE WHERE THERE IS ONLY MULTIPLE APP SERVER, THEN HOW WILL WE MANAGE CONCURRENT BOOKING:
AT APPLICATION LEVEL IF WE WILL PUT SYNCHRONIZATION AT EACH SERVER, THEN BOTH WILL REQ RESULTING IN MAKING DB BECOME AMBIGUOUS. NOW, IF CONSIDER REQ1 COMES FIRST THEN WE WILL PUT A LOCK BASED ON HIS REQUEST AND AFTER THAT WHEN REQ2 COMES WE WILL NAVIGATE IT TO SOME OTHER ROW AND EVEN IF IT TRIES TO ACCESS THE SAME ROW, WE WILL SHOW THROW SOME KIND OF ERROR TO THE APP SERVER WHICH WILL ULTIMATELY TRANSLATE ERROR TO USER SHOWING THIS ROW HAS BEEN ALREADY BOOKED. 
IF USER1 DOES NOT COMPLETE PAYMENT WITHING 10 MINUTES, THEN IT WILL RELEASE/UNLOCK THE ROW OCCUPIED BY REQ OF USER1 AND WILL TELL ALL APP SERVERS THAT THIS SEAT IS AVAILABLE NOW.
