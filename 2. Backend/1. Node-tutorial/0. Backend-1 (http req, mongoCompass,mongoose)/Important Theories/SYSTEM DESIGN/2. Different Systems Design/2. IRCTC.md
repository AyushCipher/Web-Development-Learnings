FLOW:-
USER WILL ENTER THE WEBSITE AND MAKE A REQ WITH USERNAME, EMAIL AND PASSWORD OR MAYBE PHONE NUMBER TO USER PROFILE SERVICE TO CREATE THE USER'S PROFILE AND THEN THE SERVICE STORES USER'S INFO IN DATABASE. NOW WHEN USER SERVICE DOES THIS SUCCESSFULLY IT SENDS A RESPONSE TO USER THAT PROFILE HAS BEEN CREATED WITH STATUS CODE OF 201.   

NOW IF SAME USER COMES TO WEBSITE AGAIN THEN USER PROFILE SERVICE WILL AUTHENTICATE WHETHER THE USER IS AN AUTHENTICATED USER. IF YES THEN IT WILL ALLOW USER TO ACCESS FURTHER SERVICES OF WEBSITE. 


BUT THE PROBLEMS ARISES WHEN THE MANY TYPES OF MORE SERVICES ARE ADDED TO THE WEBSITE. THEN EACH AND EVERY SERVICE MUST HAVE SOME KIND OF AUTHENTICATION MECHANISM. AND IF THAT IS THE CASE THEN WE CAN SEE SOME KIND OF DUPLICATES PROBLEM WHICH CAN BE SOLVED USING A ROUTING MECHANISM. THIS IS SOLVED USING GATEWAY.

FIRST THE USER WILL MAKE A REQ TO CREATE HIS/HER OWN PROFILE USING USER PROFILE SERVICE. USER PROFILE SERVICE WILL THEN USE EMAIL SERVICE TO AUTHENTICATE THE USER USING OTP SENDING AS VERIFICATION CODE. THEREFORE USER PROFILE SERVICE USES AUTHENTICATION MECHANISM. SO IF THE USER REQ FOR SEARCHING A TRAIN FROM STATION A TO STATION B. THEN THE USER PROFILE SERVICE WILL AUTHENTICATE THE USER AFTER GETTING A YES RESPONSE ONLY GATEWAY NAVIGATES IT TO TRAIN SEARCH SERVICE.

Q. WHERE LOCK COMES INTO PICTURE?
ANS - SEAT 1 HAS BEEN ALREADY BOOKED BY A USER AND WHILE AT THE TIME OF HIS BOOKING WE WILL PUT A LOCK(Pessimistic locking) ALONG THE WHOLE ROW OF SEAT 1. WHEN USER 2 BOOKS THE SAME SEAT 1.
