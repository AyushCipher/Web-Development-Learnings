# WHAT IS HASHING AND WHY DO WE NEED IT? 
LOAD BALANCER ROUTES TRAFFIC TO DIFFERENT SERVERS HERE THE SERVER PROBLEM IS SOLVED BUT WHEN TAKING DIFFERENT CLIENTS , SUPPOSE WHEN CLIENT 1 COMES AND REQ HIS ID AND HIS REQ GOES TO SERVER 0 WHICH THEN SERVES IT BY FETCHING INFO FROM DATABASE AND STORING PROFILE DATA IN CACHE, BUT WHAT SAME HAPPENS WITH WHEN CLIENT 2 COMES AND REQ HIS ID AND HIS REQ GOES TO SERVER 1 WHICH THEN SERVES IT BY FETCHING INFO FROM DATABASE AND STORING PROFILE DATA IN CACHE, BUT WHAT IF AGAIN CLIENT 1 REQ DATA AND THIS TIME DUE TO HEAVY TRAFFIC IN SERVER 0 HIS REQ GOT REDIRECTED TO SERVER 1, WHICH DOES NOT HAVE IT DATA STORED IN CACHE LIKE SERVER 0, THEN AGAIN IT HAD TO SERVER NETWORK REQ BY FETCHING INFO FROM DB MAKING PROCESS SLOWER. TO SOLVE THIS WE HAVE CONCEPT OF CONSISTENT HASHING IN WHICH EACH EACH CLIENT GETS HASH VALUE WHICH WHEN MODDED WITH N GIVES VALUE B/W 0 TO N-1 WHICH IS THE EXACT VALUE FROM WHICH SERVER CLIENT REQ SHOULD BE REDIRECTED.


PROBLEMS WITH HASHING TECHNIQUE:-

1. HORIZONTAL SCALING: STORM OF CACHE MISSES AS NO OF SERVERS INCREASED BCZ ALL KEYS GOT REARRANGED AND MOD VALUE COMES DIFFERENT. WE STORE REDUNDANT DATA HERE.

It will be solved using consistent hashing
